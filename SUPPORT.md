# Support

This is the default support policy for every `swarm-routing` repository that
does not have its own `SUPPORT.md`. The org is a research project maintained
on a best-effort basis, in public.

## Where to ask

- **A bug or a wrong result**: open an issue in the repository it concerns,
  with the *Bug report* form (what you ran, the seed, what you expected, what
  you got).
- **A feature, mechanism or comparator**: open an issue with the
  *Enhancement* form. Read the repository's `AGENTS.md` and the org
  [ROADMAP](https://github.com/swarm-routing/.github/blob/main/ROADMAP.md)
  first: it lists what is planned and what is deliberately out of scope.
- **A question about usage or behaviour**: open an issue with the *Question*
  form (label `question`) in the repository it concerns; if you do not know
  which, ask in [`swarm-routing/.github`](https://github.com/swarm-routing/.github/issues).
  Answers stay public so the next person finds them.
- **A security vulnerability**: never in a public issue; follow
  [SECURITY.md](https://github.com/swarm-routing/.github/blob/main/SECURITY.md).
- **Contributing a fix**: [CONTRIBUTING.md](https://github.com/swarm-routing/.github/blob/main/CONTRIBUTING.md#outside-contributions)
  (DCO sign-off, inbound = outbound licensing); issues labelled
  `good first issue` or `help wanted` are good places to start.

## What there is not

There is no private support, no email support, no chat channel and no
service-level agreement. Expect a reply within days, not hours. Conduct in
issues and pull requests follows the
[Code of Conduct](https://github.com/swarm-routing/.github/blob/main/CODE_OF_CONDUCT.md).
