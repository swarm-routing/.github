# Tools, workflows and their checks

The reference for `swarm-routing/.github`: every file and directory it holds,
every self-test and read-only run, and how a change to a reusable workflow is
proven. [`AGENTS.md`](../AGENTS.md) keeps the short version and says when to
read this page: before adding, changing or running a tool or a workflow here.

## Layout

## Validating a change to a reusable workflow


A change to `reusable-ns3-ci.yml` is validated by running its step scripts in
an `ns3-dev` image against `swarm-routing/sim-containers`' `test/fixtures/`
module (see that repo's AGENTS.md), then by a caller repo's PR (a change to
the dependency canary, `canary-dependencies` (#411), also by a
`workflow_dispatch` of that caller's branch, since the canary leg never runs
on a PR: the PR run must show no `canary` leg, the dispatch one, non-blocking;
a change to the docs-only skip, `docs-only-paths` (#505), also by a draft PR
that touches only a `.md` file, opened against a caller branch that points
its `uses:` at the change: every `ns-<ver> <profile>` leg must report green
with no image pulled, while the branch's own PR builds).
Callers pin `dependencies` to released tags (`@vX.Y.Z`; `git clone --branch`
takes a tag) and name `@main` in `canary-dependencies`, with a `schedule:` in
their `on:`. A change to
`reusable-python-ci.yml` runs `python-ci-selftest.yml` on its PR (a fixture
tool run only as a child process must read 100 % covered, #480, and a module in
the second of two `source` directories too, #530). A change to
`reusable-licence-check.yml` runs `licence-check-selftest.yml` on its PR (the
gate passes on this repository through the ci-tools image; a failing tree is
proven by `go test ./internal/checkheaders/` and, for the switch to Go, by a
caller's PR, #531). A change to
`reusable-go-ci.yml` runs `go-ci-selftest.yml` on its PR: the `good` fixture
module must pass every check with 100 % coverage in both the Go profile and
the Cobertura `coverage.xml`, and the `bad` one, called with
`fail-on-findings: false`, must report exactly `gofmt vet staticcheck test`
in the `failed` output (govulncheck is proven clean only: a vulnerable
fixture dependency would raise a real alert here). Locally, in a fixture
directory with the `toolchain` Go: `gofmt -l .`, `go vet ./...`,
`staticcheck ./...`, `govulncheck ./...`, `go test -race ./...`.
